## 1 · 2.1 语义字段恒空（P0，本票主战场）

### 1.1 根因（主控读代码定位，非推测）

`09_工程脚本/bcw_work_system/meeting.py` 构造 advice pack 处（约 590-602 行）：

```python
"consensus": parsed_conclusions.get("consensus", []),          # 597
"disagreements": parsed_conclusions.get("disagreements", []),  # 598
"evidence": [],                                                 # 599  硬编码
"risks": [],                                                    # 600  硬编码
"recommended_validations": [],                                  # 601  硬编码
```

两条独立成因：

1. **三个字段结构上永远不可能有内容**：`evidence` / `risks` / `recommended_validations`
   是**字面硬编码 `[]`**，自 `2896cfba feat(ruizi): add meeting and SPW evidence gates`
   起就是空的，没有任何代码路径往里写。
2. **另两个走一个只认 markdown 标题的解析器，认不出就静默变空**：
   `_parse_meeting_conclusions`（约 474-511 行）只在遇到
   `^#+\s*共识` / `### consensus`（及分歧对应）时才进入收集态；
   其它格式（如 `CONSENSUS: xxx`、`- 共识：xxx`）一律落到
   `return {"parsed": False, "consensus": [], "disagreements": []}`——
   **注意 `parsed: False` 这个信号被丢弃了**，调用方只 `.get("consensus", [])` 取走空列表。

**后果**：每一次 `status="completed"`、`validate_advice_pack()["valid"] is True` 的会议，
在结构上都不可能携带共识或分歧。而消费方看到的是"合法的完成"。

### 1.2 不要修错地方（主控已排除）

- `diverge_merge.py:105-125` 的 `detect_consensus` **本身逻辑是对的**（跨 pack 求共识交集）。
  它恒返回 `[]` 是**上游喂空**的后果。**改它是治标，且可能引入真 bug。**
- `validate_advice_pack`（`meeting.py:457-471`）当前只查 schema / 禁填字段 /
  decision_authority / formal_decision_created，**完全不查语义空**。
  全仓 `grep ADVICE_SEMANTIC_EMPTY` = **0 处**——WO-0055 验收第 1 条确实还没做。

### 1.3 复现（不调真模型、不花钱、可反复跑）

脚本原文见 `D:\_Progs\02Business\AsWish\WO\WO-20260925-0055-优化工单-睿智工作流缺陷与优化.md` §4
（`FakeRunner` 注入固定 stdout，`RICH` 变量含 `CONSENSUS:` / `DISAGREEMENT:` / `RISKS:` 三行）。
**预期当前输出**：`ok = True`、`validate = True`、`consensus = []`、`detect_consensus = []`，
唯一有内容的地方是 `p['backend']['output_ref']`。
**三条都成立即缺陷在。** 先跑一遍把这个输出贴进 evidence，再动代码。

### 1.4 验收（逐条硬性）

1. `validate_advice_pack` 对「completed + 五个语义字段全空」给出
   `ADVICE_SEMANTIC_EMPTY`，且**不**使 `valid` 变 False（**不许破坏既有消费方**——
   现在有代码/prod 路径在消费 advice pack，改判 invalid 会让它们全线红）。
2. 三个硬编码 `[]` 中的 **`evidence` 与 `recommended_validations` 至少各有一条真实生成路径**
   （从会议输出提取，或从既有 PG work/run 节点派生），**不许再用字面 `[]`**。
   `risks` 若确实无从提取，**必须显式标注为"未实现/待定"**，不许静默留空。
3. `_parse_meeting_conclusions` 增加**至少一种非 markdown 格式**识别（如 `CONSENSUS:` 前缀行），
   并让 `parsed: False` 向上传播为可观测信号（advice pack 里能看见"解析失败"），
   **不许再把解析失败吞成空列表**。
4. `detect_consensus` 在 pack 非空时能真的返回共识项（**只加测试验证，不改实现**——
   见 §1.2）。
5. **新测试亲眼看过转红再改实现**：把 §4 脚本的 `consensus` 断言从"恒空"改为
   "非空 **或** 有 `ADVICE_SEMANTIC_EMPTY`"。先把断言写成必定失败的值跑一次看到 FAIL，
   失败输出原文落盘到 `.BetterCiv` 仓 `WO/evidence/` 下，再改实现到 GREEN。
   只报全绿不算完成（WO-0055 §4 第 4 条同规矩）。
