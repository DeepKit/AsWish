## 1. 已实锤的复现（2026-09-30 主控实机跑，全部可重跑）

### 1.1 根 `_build.bat` 产出的是 GUI，不是 CLI

`_build.bat` 末尾唯一一条编译命令是 `dcc64 ... -E.\bin ... AsWish.dpr`，产物 `bin/AsWish.exe`。
`AsWish.dpr` 是 `uses Vcl.Forms` 的 GUI 程序；CLI 是 `cli/AsWish.CLI.dpr`
（`{$APPTYPE CONSOLE}`），由 `cli/_build_cli.bat` 构建到 `cli/bin/AsWish.CLI.exe`。
**构建日志不标注两者差别，只能靠目录名区分。**

### 1.2 GUI 对任何无法识别的参数静默吞掉（实测）

```bash
timeout 10 cmd //c "bin\AsWish.exe foo bar"                       # EXIT=124（进程长驻被杀）
timeout 10 cmd //c "bin\AsWish.exe validate --project <真实项目>"   # EXIT=124（同样长驻）
```

两次的全部 stdout+stderr 只有一行 WebView2 的
`Failed to unregister class Chrome_WidgetWin_0. Error = 1411`，
**没有任何关于未知参数的提示，也不退出**。

根因 `src/app/AsWish.MainForm.pas:430-436`（`LIsGuiVerify := True` 在 433 行）：

```pascal
for I := 1 to ParamCount do
begin
  if (ParamStr(I) = '--gui-verify') or (ParamStr(I) = '-gui-verify') then
    LIsGuiVerify := True
  else if TDirectory.Exists(ParamStr(I)) then
    LOpenDir := ParamStr(I);
end;
```

`--project`、`foo`、`bar` 全部落进"两个条件都不满足"的路径，**什么都不做**。

### 1.3 CLI 把 `--project <dir>` 当目录名，全 skip 仍报 OK（实测）

```bash
cmd //c "cli\bin\AsWish.CLI.exe validate dogfood_gui_site_final"              # EXIT=0
# [validate] trees/function-tree.yaml: 0 error(s), 0 warning(s)
# [validate] trees/module-tree.yaml:   0 error(s), 0 warning(s)
# [validate] trees/view-tree.yaml:     0 error(s), 0 warning(s)
# [validate] trees/data-tree.yaml:     0 error(s), 0 warning(s)
# [validate] issues/doc-issues.yaml:   0 error(s), 0 warning(s)
# [validate] OK

cmd //c "cli\bin\AsWish.CLI.exe validate --project dogfood_gui_site_final"    # EXIT=0
# [validate] skip (missing): trees/function-tree.yaml
# [validate] skip (missing): trees/module-tree.yaml
# [validate] skip (missing): trees/view-tree.yaml
# [validate] skip (missing): trees/data-tree.yaml
# [validate] OK
```

第二条：`--project` 被当成 project-dir，四棵树全部 skip，
**连 `issues/doc-issues.yaml` 那一行也消失了——一共 0 项被校验，
却打印 `[validate] OK`、退出码 0**。

根因（三处叠加）：

1. `cli/AsWish.CLI.dpr:1233-1234` 是纯位置参数
   `LCommand := LowerCase(ParamStr(1)); LDir := ParamStr(2);`——
   **CLI 根本没有 `--flag` 语法**，任何 `--xxx` 都会被原样吃成目录名。
2. `RunValidate`（`cli/AsWish.CLI.dpr:845`）刻意不做 `OpenProject`
   （源码注释说明：命令的职责是报告，不能写盘），于是也**没有任何目录/`.AsWish`
   存在性检查**——所有文件判 `not Present` 即 skip。
3. skip 不计入 `LResult.Ok`，0 error 直接走 `Writeln('[validate] OK')`。

> **同文件里已有正确先例可循，不要另发明一套**：`RunDecisionsApply` /
> `RunHealth` / `RunBundleApply` 的第一步都是
> `if not TDirectory.Exists(TPath.Combine(ADir, '.AsWish'))`（163 / 208 / 257 行）。

## 2. 修复要求（默认路线；可提替代方案，但须先过主控）

### R-1 `_build.bat` 同时构建两者并打印对照表（对应 WO-0051 A-1 方案 1）
- 构建日志末尾必须有两行醒目对照，形如：
  ```
  bin/AsWish.exe          = GUI（桌面端，不要传 CLI 参数）
  cli/bin/AsWish.CLI.exe  = CLI（headless 命令行）
  ```
- 只改注释不算；必须改构建行为（两个都编）或至少在日志末尾打印该对照表。

### R-2 GUI 入口 fail-closed（对应 WO-0051 A-1 方案 2，**本单必做**）
- 无法识别的参数 → 打印用法 + **非零退出**。
- `--gui-verify` 与"已存在目录"两条合法路径必须保持可用；`--gui-verify` 12/12 断言不得回退。
- **可测性要求**：把参数解析抽成不依赖 `Vcl.Forms` 的纯函数（建议
  `src/core/AsWish.CommandLine.pas` 的
  `TAsWishCommandLine.Parse(const AArgs: array of string): TAsWishParsedArgs`，
  返回 command / dir / isGuiVerify / unknownArg），GUI 与 CLI 共用；
  否则这条没法写单测，只能人工点，等于没修。

### R-3 CLI 对 `-` 开头的位置参数 fail-closed（对应 WO-0051 A-2）
- `project-dir` 以 `-` 或 `/` 开头 → 报错退出，错误信息必须指出
  “project-dir 解析为 `--project`；CLI 只接受位置参数，不接受 `--flag`”。
- 命令需要 spec 状态而 `ADir\.AsWish` 不存在 → 报错退出（沿用 §1.3 的既有写法）。

### R-4 `validate` 全 skip 时不得报 OK
- 被校验文件数为 0 → 输出 `[validate] no spec files found under <dir>` 之类，
  **退出码非 0**。
- 有 skip 也有真校验时，OK 行必须带上计数，如 `[validate] OK (checked 5, skipped 0)`。

### R-5 单测先红后绿（纪律，不是建议）
- 每条都要**先看着它红**再修，把 RED 输出贴回本单 §4。
- R-2/R-3 用参数数组直喂解析函数；R-4 用一个确实没有 `.AsWish` 的临时目录端到端跑。
- 全量 332/332 不回退，三构建 exit 0，六门禁 PASS。

### R-6 环境约定写进文档（对应 WO-0051 轨道 B，低成本高回报）
- `AGENTS.md` 固定写明：本机用 `python`，**不要用 `python3`**（Store 占位程序，
  失败时零输出、退出码 49；本次已连踩三次"执行成功但文件没变"）。
- 本机运行本仓可执行文件一律 `> file 2>&1` 再读文件，**不要 `| tail` 直连**
  （管道缓冲写满后进程永久阻塞：实测 scan 正常 7.7s 完成，挂住 10+ 分钟不动）。
