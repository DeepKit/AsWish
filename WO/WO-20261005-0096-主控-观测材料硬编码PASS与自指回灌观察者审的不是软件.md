## 〇、缺陷分级：审计装置自己造了张全绿表

`D:/_repro/build_obs_material_v2.py` 第 45-48 行原文：

```python
"recorded_gate_verdicts": [
    {"id": g["gate_id"], "verdict": "PASS", "exit_code": 0}
    for g in manifest.get("gates", [])
],
```

**它对全部 12 道门禁无条件写死 `"verdict": "PASS"`，与真实运行零耦合。**

本次 HEAD=48ab11d 恰好 12 道门真是 PASS，所以假数据与实况一致、未造成误判。
但只要**任何一道门实跑失败**，喂给两个外部观察家族的就是一张全绿表，
而他们会在"系统已经全绿"的前提下继续找问题——
这正是 WO-0091"空的说成满的"，只不过这次是**审计装置自己造的**，
比下游开发AI自封批准人更严重：它污染的是 H5 这道"最后防线"的输入。

同一处还剥掉了 `command` / `stdout_sha256` / `claims` / `truncated`
（证据包里本来都有），导致 deepseek 报出"没有命令、没有日志哈希、没有时间戳"
这条**失实**发现。**失实结论比漏报更危险**——它会驱动错误的工单。

## 一、缺陷本体

H5 只读观测的做法是：把"描述被观测软件的材料"喂给外部模型家族，
让它们找缺陷。R1 实跑时，材料里带进了 H5 认证层自身字段
（`valid_observer_families`、`required_observer_families`、`certification` 等）。

### 1.1 后果：两个家族的发现全部作废

两个家族（deepseek、nemotron）回报的头等"阻断"都是
"缺少异构观测 / 认证 withheld"。它们审的是**观测装置自己的状态**，
不是软件。这不是观察者弄错了——**材料就是这么写的**，
材料描述的是 `valid_observer_families: []` 的系统，它们在如实报告所见。

于是 R1 的两份 raw、两条席位、全部 findings 作废重跑。
**这是本单的量化损失：整轮观测白跑。**

### 1.2 第二处笔误（同源）

`h4_patterns` 在 R1 材料里序列化成 `[null, null, null]`。
观察者看不见绕过门禁到底扫什么，于是对 H4 的评论只能是空泛的。

### 1.3 根因：这不是"忘了删字段"

只要"观测材料"与"被观测系统"共享任何自指字段，
观察结论就会有一部分指向审计装置本身。改一次字段表治不了本，
因为下一轮材料还会从同一份系统描述里生成，**又会带进新的自指字段**。

另外还有一个更隐蔽的方向：如果材料里带了"主控希望观测者得出什么结论"的暗示
（既有的 PASS 结论、既有的共识、Amy 的推荐答案），
观察者会去**证实**而不是去**找缺陷**——这与既有的"反框架偏差"纪律同源，
但那套纪律目前只管会议，没管观测材料。

## 二、执行阶段

### 阶段 1：门禁判定必须读真值，不得硬编码（必做，先做这条）

材料里的门禁判定只能有一个来源：**当前证据包的 `deterministic_gates[*]`**。

- 生成器必须接收证据包路径为**必填参数**，缺路径直接失败，不得静默回退到
  "全部 PASS"或空表；
- `verdict` / `exit_code` / `command` / `stdout_sha256` / `claims` / `truncated`
  一律从实体字段原样取用，**不许在材料里另造一份精简字段表**——
  精简就是失真（本次 deepseek 的失实结论即由此而来）；
- 证据包不存在或字段缺失 → 生成失败，不得生成"看起来完整"的材料；
- 计数器事实测：把证据包里任意一门的 verdict 改成 FAIL → 材料必须反映 FAIL；
  改不成 FAIL 的材料生成器即为未修好。

### 阶段 2：材料生成时强制剔除自指字段（必做）

观测材料的生成器必须有一张**显式的剔除表**，至少覆盖：

- H5 认证层：`valid_observer_families` / `required_observer_families` /
  `external_observations` / `observer_seat_outcomes` /
  `h5_observation_verdict` / `certification` / `pending_h5_findings`
- 观测输入链：`runtime_contract.observer_input` / `observer_models` /
  `observer_family_whitelist` / `observations_sha256` / `min_observer_families`
- 任何名称含 `observ` / `certif` / `h5_` 的字段

剔除必须在**生成时**执行，不是事后手改。产物记 `material_sha256`。

### 阶段 3：剔除表自身也要被校验（必做）

- 生成器必须**自证**：对产物做一次扫描，若产物中出现剔除表内任何键名
  → 生成失败 fail-closed。
- 计数器事实测：把某个自指字段塞回去 → 生成器必须失败。

### 阶段 4：观察材料不得夹带结论暗示（必做）

材料不得包含任何形式的"预期结论"：

- 门禁判定以**中性事实**形式原样呈现（含真实命令与日志哈希），
  不得附带"已复核通过"之类表述，也不得精简成只剩 id/verdict/exit_code；
- 不得包含主控/Amy 的推荐答案、既有共识摘要、法源列表中足以预定结论的内容；
- prompt 只问事实问题，不提供倾向性框架（与反框架偏差纪律一致）。

### 阶段 5：README 写明（必做）

`tools/spw-evidence/README.md` 增加"观测材料边界"节：材料里有什么、为什么没有自指字段、
谁有权增删剔除表条目（主控，改动须显式记录理由）。

## 四、禁条

1. **不得**用"把 `valid_observer_families` 从材料里删掉"这种方式交差——
   必须落到显式剔除表 + 自证扫描，否则下一轮又会漏新字段。
2. **不得**为了让观察者"少走弯路"而在材料里给出结论提示——
   那会把 H5 变成盖章仪式。
3. **不得**在材料里保留任何"审计装置自身健康度"信息。
4. **不得**在材料里硬编码任何门禁判定。判定只能有一个来源：当前证据包实体。
   凡写死 `"verdict": "PASS"` 的代码，无论本次是否巧合正确，一律视为 P0 级缺陷。
5. **不得**把证据包的完整字段精简成"好看的三字段摘要"——
   精简即失真，本次失实结论正由此产生。
