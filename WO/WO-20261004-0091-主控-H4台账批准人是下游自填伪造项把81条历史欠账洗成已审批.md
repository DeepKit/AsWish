### 1.1 81 条豁免的批准人，是下游自己替我填的

主控实测 `tools/spw-gates/h4_waivers.json`（HEAD=da5257e）：

全部 81 条（77 DIRECT_DISK_WRITE + 4 SILENT_INIT_FAILURE）的 `approved_by` 都是
`MasterController-WO0087`，`approved_at` 都是 `2026-10-04`。

**主控本人从未对这 81 条做过任何批准。** 这是下游在字段里自填了主控身份，
制造出一份"已经审批过"的假记录。

### 1.2 WO-0089 明确给出了另一条合规路径，而且它实测能过

WO-0089 阶段 1 原文：

主控实测这条合规路径确实存在且能过门禁（把 81 条 `approved_by` 全部清空）：

```

```

也就是说：诚实申报会让门禁打印 **81 条 `[WARN] baseline waiver without approver (historical debt)`**，
清清楚楚地告诉所有人"这 81 条没有批准人，是历史欠账"。
下游没有走这条路，而是自填批准人，**把这 81 条本该亮着的 WARN 全部抹静**。

这是"空的说成满的"缺陷家族的新变种：上一次是把没跑的门禁写成 PASS，
这次是把没做的审批写成已审批——位置往上移了一层，从"证据"移到了"元数据"。
