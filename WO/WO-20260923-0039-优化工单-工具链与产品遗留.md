## 轨道 A · AI 工作台 / 会议系统（高杠杆，影响全部项目线）

### A-1（P0）invoke 两条 provider 通道全断 —— BUG-M5 + M6
- **症状**：wisegateway 三档模型全 422（请求体缺 `channel`）；claude-code 传未知参数 `--safe-mode`。
- **影响**：`specialist_run_ref` 经 invoke 无法产生 → 非快路径的专业任务全被卡或被迫走旁路。
- **方案**：
  1. wisegateway 客户端请求体补 `channel` 固定字段（值问网关侧或从 model-roles.yaml 读）；
  2. claude-code provider 按本机 `claude --help` 动态生成参数集，不硬编码版本敏感项；
  3. **两条通道各加一条 e2e 冒烟测试进 CI**（这是根因：两条同时坏说明从未冒烟过）。
- **验收**：`invoke --provider wisegateway|claude-code` 各跑通一次真实任务并产出 specialist_run_ref；冒烟测试绿。

### A-2（P1）roundtable 默认配置必挂 —— BUG-M2
- **症状**：默认 session-dir 落在项目区，six-hats 后端强制 `D:/BCW/runs/bcw/**` → 首跑必崩。
- **方案**：roundtable-init 默认值改为 `D:/BCW/runs/bcw/roundtable/<task_id>`；写边界常量两边共享单一来源，禁止两处各自硬编码。
- **验收**：不带 `--session-dir` 从 init 跑到第一个帽 step 不报边界错误。

### A-3（P1）会议席位不足仍静默开会 —— BUG-M3 + M4
- **症状**：2/3 专家"无法反查家族"仍照开；跑题发言（域名 SEO 答代码题）与幻觉规范（引用不存在的"签名约束"）无拦截。
- **方案**：
  1. 会前池探测，可用席位 < 配置下限 → `MEETING_NO_QUORUM` fail-closed；
  2. 白帽输出引用"规范/条款"必须带文件:行号，无定位自动标 `unverified` 不进主持摘要；
  3. 修复模型家族反查表（qoder-GLM-5.2 / qoder-Kimi-K3 无法解析家族，关联旧账 BCW-TD20260811-002）。
- **验收**：拔掉 2/3 席位模拟跑会 → 拒绝开会而非空转；构造一条无出处"规范"引用 → 摘要中被标 unverified。

### A-4（P1）spw gate 引号语义 —— BUG-M8 通用面
- **现状**：AsWish 已按"单一路径参数直调"规避；spw.py 通用缺陷仍在——任何项目写 `cmd /c "A && B"` 型 gate 必挂且报错无提示。
- **方案**：gate 定义增加可选 `cwd` 字段（runner 设置进程工作目录）；文档化 cmd 引号保留行为；`不是内部或外部命令` 时错误输出附加一句 cmd 引号提示。
- **验收**：含 `&&` 链 + cwd 字段的 gate 可跑通（或 runner 直接拒绝该形态并给出替代写法）。

### A-5（P2）身份链文档与错误消息 —— BUG-R1/R2/R3/R4
- 直子命令契约对齐（或文档删承诺）；work_id 前缀与"由 work-start 生成"写入错误提示；query_kind 枚举进 details；嵌套 payload 报专错。
- **验收**：四个错误场景各触发一次，新消息含自助恢复指引。

### A-6（P2）新项目首单认领 —— BUG-R5
- 提供受控 action 注册入口或 `work-start --create-action`，杜绝"借挂不相关 action"污染台账。
- **验收**：新仓库首单挂本仓 action，PG 归属字段语义正确。

## 轨道 B · AsWish 产品遗留（源自 2026-09-22 代码审查，验证过、未修的项）

### B-1（P1）Edge WebView2 吞键冲突
- **症状**：`DoFormKeyDown` 的 `ActiveControl is TCustomEdit` 白名单不含 Edge 浏览器控件；焦点在 WebView 时按 1-9 可能同时被表单和内核处理。
- **方案**：白名单加 TCustomEdgeBrowser；或焦点在浏览器内时完全放行（HTML 侧自建快捷键）。
- **验收**：浏览器有焦点时桌面快捷键不触发；0-9 输入进 HTML 不双触发。

### B-2（P2）提交/拒绝后 HB Deck 状态残留
- **症状**：`ExecuteCommitmentGate` 成功后不清 `FLastChangeSetId`，UI 可重复点 Commit/按 Enter。Controller 侧幂等已加（e0c9181），但 Deck 状态观感仍错（显示"CsId: cs-xxx"像未提交）。
- **方案**：提交/拒绝成功后置空 LastChangeSetId 并刷新 Deck 状态行为 `[Idle]`。
- **验收**：单测断言提交后 LastChangeSetId=''，按钮点击不再触发 ExecuteCommitmentGate。

### B-3（P2）Providers.pas BOM 缺失核查
- **症状**：上轮 diff 中 BOM 被移除；当前文件纯 ASCII 无害，但今后加中文注释即乱码。
- **方案**：`.gitattributes` 声明 `*.pas text working-tree-encoding=UTF-8-BOM`（或确认 Delphi 13 无 BOM 行为后留档）。
- **验收**：加一条中文注释 → Delphi IDE 显示正常 → 删除后 commit。

### B-4（P2）Difference YAML 转义与降级判据
- **症状**：① `WriteDifferenceFile` 的 `EscapeStr` 不转义换行，Note 含 `\n` 破坏 YAML；② `AAllowDegraded` 仅对 `TreeType='view'` 生效，function/module 树证据缺失时不标降级。
- **方案**：① 转义补 `\n`→`\\n` 或 Note 改用块标量；② 降级判断按"有无 comparator 覆盖"与树类型解耦，无覆盖即标降级。
- **验收**：带换行 Note 写读往返一致；function 树无证据 + AllowDegraded → IsDegraded=True。

### B-5（P2）Binding 遗留
- **症状**：① `emaReframe` 非 frameRejection 路径把 `SubmitUserIntent` 的树类型硬编码 `ttFunction`，view/module 上下文走错树；② `ProcessEhaiAction` 中 `LReviewText` 赋值后弃用。
- **方案**：① 用 `AAction.Context` 携带的树信息或 ObservableObjectRef 反推真实树类型，取不到则问用户不猜；② 把 review 文本接入 Deck 状态行展示。
- **验收**：view 节点上提交 free input 落到 view 树；Deck 显示评审摘要。
