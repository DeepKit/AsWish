# WO-20260930-0063 · Pascal 源文件 UTF-8 BOM 丢失导致中文乱码（WO-0061 修复引入的回归）

- **提出人**：主控（审计 WO-0060/0061/0062 下游交付时发现）
- **归属仓库**：`D:\_Progs\02Business\AsWish`
- **上游**：`WO/AUDIT-VERDICT-20260930-0060-0061-0062.md`。WO-20260930-0061 的修复本身是对的，
  但它的实现提交 `50e9c4b` 在重写 `src/app/AsWish.MainForm.pas` 时丢掉了 UTF-8 BOM。
- **优先级**：P1（GUI 中文界面 + `difference.html` 标题对用户可见乱码；331/331 全绿证明不了它）
- **结论先行**：**这个仓有一类"测试一致地绿、用户一致地看到乱码"的缺陷，而且它已经发生了。**
  dcc64 编译不带 BOM 的 Pascal 源时按 ANSI/GBK 读，UTF-8 的中文字面量在运行时会变乱码。
  因为断言里的中文和 GUI 渲染的中文编译自同一份乱码字节，**测试永远通过**。
  我已在两个文件上实测到用户可见的乱码，其中一处是由 WO-0061 的修复提交引入的。

### 1.2 乱码不是推测，是两个文件实测

**`src/services/AsWish.Services.RenderDiff.pas`**（无 BOM `756e69`，12 行中文，其中第 54 行
`LT(ALocale, 'Structural Difference & Judgment', '结构差异与裁决')`）：

重建 CLI 后对任意有差异的项目跑 `difference`，产物 `difference.html` 的标题字节实测为
`\xe7\xbc\x81\xe6\x92\xb4...`，GBK 解出来是 `缁撴瀬宸紝涓庡鍐`——
**不是** `结构差异与裁决`。用户打开这个 HTML 就看到乱码标题。

**`src/app/AsWish.MainForm.pas`**（27 行中文，第 2260 行）：

```pascal
if Pos('经验总结，非可复核记录', FGhostsLabels[0].Caption) <= 0 then
```

这一行是 `--gui-verify` Step 8 的 DOM 断言。中文字面量和 GUI 里 FGhostsLabels 的 Caption
**编译自同一份乱码字节**，所以断言会通过——但用户屏幕上那一行也是乱码。
WO-0061 把 Step 8 从"假 PASS"改成"真断言"的努力，在编码这一层会被抵消。

### 1.3 为什么 331/331 拦不住，六大门禁也拦不住

同类文件 4 个：

| 文件 | 头三字节 | 中文行 |
|---|---|---|
| `src/app/AsWish.MainForm.pas` | `7b203d` 无 BOM | 27 |
| `src/services/AsWish.Services.RenderDiff.pas` | `756e69` 无 BOM | 12 |
| `tests/Test.AsWish.GUIDecisions.pas` | `756e69` 无 BOM | 281/283/285 |
| `tests/Test.AsWish.EHAI.Binding.pas` | `7b203d` 无 BOM | 301/305/361 |

后两个测试文件是"一致性损坏陷阱"的标本，`tests/Test.AsWish.GUIDecisions.pas`：

```pascal
LBadgeText := '这类分叉曾错在 ' + ... + ' [经验总结，非可复核记录]';
Assert.IsTrue(LBadgeText.Contains('[经验总结，非可复核记录]'), ...);
```

两边都从乱码字节来，所以 `Contains` 恒真。**测试绿 ≠ 运行时文本对。**

`tools/spw-gates/gate_encoding.py` 只查 NUL 字节、UTF-8 可解码性、CRLF/LF 混用，
**完全没有 Pascal BOM/代码页这一维**，所以整类回归可以无声通过所有门禁。

## 2. 修复要求（默认路线，承接方可提替代方案但须先过主控）

1. **R-1 恢复 BOM**：给 §1.3 表里 4 个文件补回 UTF-8 BOM（`efbbbf`），
   **内容一个字节都不要改**，只在文件头插 BOM。补完 `git diff --stat` 必须显示
   4 files changed, 4 insertions(+), 4 deletions(-) 这种量级——如果 diff 出现大段改动，
   说明你顺手重构了，退回重做。
2. **R-2 用户可见面验证（硬门，不许用测试代替）**：
   - 重建 CLI → 对已知有差异的项目跑 `difference` → `difference.html` 标题必须能
     UTF-8 解码成 `结构差异与裁决 - AsWish`（验收时贴出实际字节与解码结果）。
   - 重建 GUI → `--gui-verify` 在有 WebView2 的机器上 Step 8 必须真过；
     同时用截图/`SaveWindowScreenshot` 证据确认界面中文不是乱码。
3. **R-3 门禁补编码维（防再犯）**：在 `tools/spw-gates/gate_encoding.py` 加一条规则——
   `src/`、`cli/`、`tests/` 下所有 `.pas`/`.dpr`/`.inc`，**凡含非 ASCII 字节的必须带 UTF-8 BOM**；
   不带即 FAIL，并在 finding 里给出文件与首个非 ASCII 行号。
   **必须做反向对照**：临时删掉一个文件的 BOM，门禁必须 FAIL；恢复后必须 PASS。
   只跑绿不算有防护（参见 `feedback_test_must_go_red_and_grep_binary`）。
4. **R-4 一致性损坏陷阱的兜底**：为 R-3 再补一个单测（放 `tests/`，命名随既有惯例），
   扫描上述三个目录的 Pascal 源，断言"含中文 ⇒ 有 BOM"。这是给未来人的红灯，
   不是给现在的。先看它红，再修，再绿。
5. **纪律**：每提交 ≤200 行；R-1 与 R-3/R-4 分开提交；先写 R-3/R-4 的 RED 证据再修 R-1
   （顺序可以是 R-3/R-4 先红 → R-1 修复 → R-3/R-4 转绿）。
