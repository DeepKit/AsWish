## 轨道 A · 屏幕捕获 API 的静默失败（P1，影响所有 VCL 取证）

### A-1 `PrintWindow` 把空捕获报成成功
- **复现**：对未上屏的 VCL 窗体下的 `TCheckBox`（132x28）调
  `PrintWindow(hWnd, dc32bpp, 0)`，返回 TRUE，结果为一片均匀 `clBtnFace`
  （实测 3696 像素只有 1 种颜色）。调用方按返回值判定成功 → 写出空白证据图。
- **方案**：调用后必须校验"distinct colors > 1"或"与预期的背景色不同"，
  否则视为捕获失败并上报（含控件 rect、窗体 `IsWindowVisible`、WindowState）。
- **验收**：构造一个未上屏窗体 → 调用方拒绝出图并报出可归因诊断，而不是写出白图。

### A-2 `GetWindowDC` + `BitBlt` 把空捕获报成成功
- **复现**：同样场景下返回 TRUE，结果为**纯黑**（3696 像素单一颜色 (0,0,0)）。
  与 A-1 同样静默。
- **方案**：同 A-1，统一走同一个"捕获守卫"。
- **验收**：同 A-1；另需覆盖"窗体上屏但被遮挡"这一变体（捕获到遮挡物内容，
  需能识别为可疑而非当成正常证据）。

### A-3 把"捕获守卫"下沉为共享设施（本条是 A-1/A-2 的正解）
- **现状**：本次已在 `AsWish.MainForm.pas` 的 `--gui-verify` harness 内实现
  （断言 `IsWindowVisible` → 拒绝 distinct colors ≤ 1 → 每次落
  `[CAPTURE-DIAG]` 诊断行）。修完 BUG-B 后实测控件捕获 distinct colors
  80（未勾选）vs 85（已勾选）、md5 不同，勾选态在像素层可验证。
- **方案**：将该逻辑从本项目 harness 提到 `00Common/skills/` 下作为共享工具，
  供 axis / compare 等其他 VCL 取证场景复用；禁止每个项目各写一份。
- **验收**：第二个 VCL 项目接入时零自定义捕获代码即可拿到"带守卫的控件截图"。

## 轨道 B · 取证前置条件与证据格式（P1）

### B-1 `DoShow` 会在窗口创建期提前触发（根因，AsWish 侧已修，需沉淀为通则）
- **复现**：`AsWish.Shell.Form.pas:487` 的 `DoShow` 触发 `AfterShellShown`；
  而 VCL 的 `TWinControl.CreateWnd` 在 `Visible` 已为 True 时会提前触发
  `CM_SHOWINGCHANGED`/`DoShow`。于是整个 `--gui-verify` 跑在
  `Application.CreateForm` 内部，`Application.Run` 还没 `ShowWindow`。
- **症状**：`TWinControl.Visible = True` 而 `IsWindowVisible(Handle) = False`。
- **易错点（已踩）**：此时调 `TWinControl.Show` 是**空操作**（VCL 属性已是
  True），必须走 `ShowWindow(Handle, SW_SHOW)`。
- **方案**：任何"自动化驱动 GUI 取证"的 harness，第一件事是断言
  `IsWindowVisible`，不满足先 `ShowWindow` 再不满足则 fail-closed 拒绝出证据。
  建议在共享工具里提供 `AssertFormOnScreen(AForm)` 一元过程。
- **验收**：把 `ShowWindow(Handle, SW_SHOW)` 那三行从 AsWish 删掉，
  共享工具的守卫应立刻 fail 并给出可归因诊断。

### B-2 `TBitmap.SaveToFile` 无视扩展名一律写 BMP
- **复现**：`SaveControlImage` 把 BMP 内容写进 `.png` 路径，文件魔数
  `42 4d`（"BM"）可直接证实。下游按 PNG 解析即失败，或更糟——当成不透明
  二进制收下，证据链在格式层面就已经不诚实。
- **方案**：写 `.png` 一律走 `TPngImage.Assign` + `TPngImage.SaveToFile`。
  可在编码守卫 gate 里加一条"证据图片扩展名 ↔ 魔数"一致性检查。
- **验收**：向 `WO/evidence/screenshots/` 投一个 `.png` 实为 BMP 的文件，
  gate 必须报错。

### B-3 `TCustomForm.GetFormImage` 走 `PaintTo`，不反映控件实时状态
- **复现**：`Vcl.Forms.pas:9733`，`PaintTo(Result.Canvas.Handle, Ofs, Ofs)`。
  `Checked=True` 的 `TCheckBox` 在窗口截图里与 `Checked=False` 时**字节相同**。
- **影响**：窗口截图不能作为"勾选态/选中态"这类状态可视证据；状态证据必须
  靠控件级捕获或确定性断言（`[STATE]` 日志行）。
- **方案**：`SaveWindowScreenshot` 保留 `GetFormImage` 作底（它仍是唯一能拿到
  VCL 布局的方式），但证据链须明确声明"窗口截图不含控件实时状态"，
  状态类断言一律另出控件级捕获。
- **验收**：WO-0049 的 `gui-10/11-consent-checkbox.png` 需保持像素级可区分，
  且日志里 `[STATE]` 行与像素结论一致。
