## 一、目标

开发前，把 View Spec 渲染成可确认的视觉规格基线。链路：

```text
Natural Language → CandidateIngest/Decisions → View Spec → Visual Preview → Human Decision → Accepted Visual Baseline
```

本票**不负责**开发后截图比对。

## 二、核心架构纪律

1. **人类不直接编辑 Spec**：复用 `CandidateIngest` 自然语言输入，不增 YAML 编辑器 / 字段编辑器 / WYSIWYG。
2. **决策复用现有 Decisions**：禁止 `VisualDecision` / `VisualApproval` / `VisualProposal` / `VisualReviewState` 等新实体。
3. **跨投影复用 `semantic-bundles`**：禁止 `ViewImpactGraph` / `ProjectionImpactMap` 等新图。

## 三、唯一核心产物：Accepted Visual Baseline

语义：被人类确认、与当前 Spec 状态绑定的视觉规格基线。不是设计稿、不是截图，是 **View Spec 的可渲染、可复核、可交付视觉表现**。

**基线实体复用现有 `SpecSnapshot`（主控钉死）**：不得新建独立 Baseline 实体。`Accepted Visual Baseline` = 现有 `SpecSnapshot` 增加视觉绑定（view-tree 引用 + `renderer_version` + `decision` 引用），字段优先复用现有协议。

## 四、Visual Preview：第一阶段 = 结构线框（主控钉死）

- 输入：`view-tree`（必要时经 `semantic-bundles` 取 function/module/data 上下文）。
- 输出：Reviewable Visual Preview（HTML / WebView2 / SVG）。
- **保真度边界**：`TSpecNode` 无布局字段（layout/position/bounds 均缺），View Tree 是需求侧结构树。故第一阶段 Preview = **结构线框（wireframe）**，确定性渲染「页面→区域→组件→层级」，**不承诺相对位置 / 尺寸**。
- 若要表达位置/尺寸，需先扩展 View Spec 布局 schema（**另立协议票，本票不做**）。

## 五、确定性渲染（主控钉死）

1. 相同 View Spec + Renderer Version → 相同 Preview。
2. 第一阶段**纯确定性映射渲染**（view-tree → 模板渲染），**不引入 LLM 视觉解释**。
3. 若未来引入 LLM 视觉解释，必须 AI Interpretation 与 Render 分离（本票不做）。

## 六、Screenshot vs Visual Preview（须写入文档）

```text
Screenshot = Implementation Evidence
Visual Preview = Specification Representation
```

## 七、Baseline 创建方式

Preview 形成后，人类自然语言确认（"这个版本就是我们要开发的页面"）→ 现有 Decisions 正式裁决 → Accepted Visual Baseline。**不得因 Preview 生成成功自动成为 Baseline。**

## 八、自然语言变更（复用 0027A–D，不新建）

"返回按钮移到底部" → `CandidateIngest` → Decision Confirmation → Spec update → Preview regenerate。

## 九、Agent 交接（概念澄清）

Accepted Visual Baseline 与 Accepted Spec + View Spec + Relevant Decisions 一起，**通过现有 `context-pack` / `semantic-bundles` 关联导出**。不引入"Agent bundle"新概念。本票不开发新 Agent。
