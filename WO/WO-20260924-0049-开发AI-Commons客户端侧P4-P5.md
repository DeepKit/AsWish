### 睿智工作流工具链 BUG 记录（P-4 收尾阶段发现，均已定位并修复）

老板指令要求"记录在使用睿智工作流时的 BUG，提出优化建议和解决方案"。以下是本次
P-4 收尾（补 GUI 实机证据）过程中定位到的三个缺陷，全部有复现路径与修复，非推测。

**BUG-A · `Vcl.Edge` 文件式 `CapturePreview` 持独占句柄不释放（已修）**

- 复现：`Vcl.Edge.pas:1019` 用 `SHCreateStreamOnFile(PChar(AFilename),
  STGM_READWRITE or STGM_CREATE, Stream)`——无共享模式。WebView2 在完成回调之后
  仍长期持有该句柄，读取即 sharing violation，临时文件永远无法回收。`E:/temp`
  实测残留 7 个 47 KB PNG + 1 个 0 字节文件。
- 次生缺陷：旧代码等待 4000 ms，而实测单次捕获 7–9 s，即每次必超时；且删除动作写在
  成功分支里，超时路径根本不删 → 每跑一次 `--gui-verify` 泄漏一批文件。
- 修复：改用 `TStream` 重载（`Vcl.Edge.pas:1042`，`TStreamAdapter.Create`）直接写
  `TMemoryStream`，全程无文件句柄；stream 存进 `FPendingStream`，确保 WebView2 RPC
  线程可能仍在写入时不被释放。
- 附带发现：WebView2 拒绝在页面尚未稳定时下发捕获（stream 重载返回 `$80004005`、
  size=0，11 次里 6 次，且每次都紧跟导航）。加一次有界重试（`Sleep(800)` +
  重置 stream size）即全恢复，不延长快失败路径。

**BUG-B · `--gui-verify` 全程跑在"主窗体未上屏"状态（已修，影响面最大）**

- 复现：`AsWish.Shell.Form.pas:487` 的 `DoShow` 触发 `AfterShellShown`；而 VCL 在
  `TWinControl.CreateWnd` 里，若 `Visible` 已为 True 就会提前触发
  `CM_SHOWINGCHANGED`/`DoShow`。于是整个 `--gui-verify` 实际跑在
  `Application.CreateForm` 内部，`Application.Run` 还没来得及 `ShowWindow`。
- 症状：`TWinControl.Visible = True` 而 `IsWindowVisible(Handle) = False`。
- 后果（静默）：所有基于屏幕像素的捕获 API 都返回"空图"且**不报错**——
  `PrintWindow(hWnd, dc, 0)` 返回 TRUE 但只涂出一片均匀 `clBtnFace`；
  `GetWindowDC`+`BitBlt` 返回 TRUE 但涂出纯黑。两者看起来都像成功。
- 修复：取证前先 `ShowWindow(Handle, SW_SHOW)`；仍不可见则硬失败并拒绝出证据。
  注意 `TWinControl.Show` 在这里是空操作（VCL `Visible` 已是 True），必须走 Win32。
- 对老板第三步（"用在 axis/compare 上，测 UI 与实际完成结果的差距"）的直接意义：
  修复前 `gui-01..gui-09` 全是 `PaintTo` 渲染而非屏幕截图，结构上无法支撑该差距测试。

**BUG-C · `TBitmap.SaveToFile` 无视扩展名，一律写 BMP（已修）**

- 复现：`SaveControlImage` 把 BMP 内容写进 `.png` 路径。文件魔数 `42 4d`（"BM"）
  可直接证实。证据链上任何按 PNG 解析的下游都会失败，或更糟——把它当不透明二进制
  收下。
- 修复：改走 `TPngImage.Assign` + `TPngImage.SaveToFile`，扩展名与内容一致。

**优化建议 · 把"捕获守卫"从 harness 提升为共享设施**

根因抽象出来是一类：**VCL 没有"这个控件真的在屏上"的取证级断言，而两个屏幕捕获 API
都把空捕获报成成功**。建议方案（本次已在 harness 内实现，应下沉为共享工具）：

1. 捕获前断言 `IsWindowVisible`，不可见即拒绝出证据；
2. 捕获后拒绝"distinct colors ≤ 1"的图像——空图不是证据；
3. 每次捕获落一条 `[CAPTURE-DIAG]`：控件 rect + 窗体 Visible + WindowState +
   IsWindowVisible + distinctColors，让失败可归因、不必整轮重跑。

**仍未闭合的取证缺口（非本次范围，需单列工单）**

`SaveWindowScreenshot` 仍以 `TCustomForm.GetFormImage`（`Vcl.Forms.pas:9733`，
内部走 `PaintTo`）为底，而 `PaintTo` 不反映 `TCheckBox` 的实时勾选状态——实测
`Checked=True` 时窗口截图与 `Checked=False` 的旧控件截图字节相同。故勾选态的可视证据
必须靠独立的控件捕获（`gui-10/11-consent-checkbox.png`）而非窗口截图。
