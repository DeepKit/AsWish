## 任务（单事项）

**已核实的代码事实**，`.github/workflows/build.yml:38-45`：

```yaml
      - name: Deterministic gates (vendored-upstream drift / open-source export)
        run: |
          python -X utf8 ..\tools\spw-gates\gate_ehai_vendor_drift.py
          if errorlevel 1 exit /b 1
          python -X utf8 ..\tools\spw-gates\gate_open_source_build.py
          if errorlevel 1 exit /b 1
```

该 step **没有 `working-directory`**，GitHub Actions 的 `run` 默认在检出根
（`$GITHUB_WORKSPACE`，即仓库根）执行。所以解释器找的是
`<repo>/../tools/spw-gates/...`——**检出目录的上一级**，也就是仓库外面。
干净克隆里那个位置不存在，python 直接以"系统找不到指定的路径"退出。

**这两个脚本的真实位置是 `tools/spw-gates/`（就在仓库根下）**：

```text
tools/spw-gates/gate_ehai_vendor_drift.py
tools/spw-gates/gate_open_source_build.py
```

本机 `..\tools\...` 能跑通只因为本机恰好有个平级目录结构，属于
**本地巧合，不是正确路径**。开源后第一个外部 PR 就会撞上。

## 修复要求（默认路线，下游不得反问）

**第一步——改路径**：把两处 `..\tools\spw-gates\` 改为 `tools\spw-gates\`，
顺手补 `working-directory: ${{ github.workspace }}` 明示，消除"依赖默认值"
的隐式约定。

**第二步——路径改为从清单推导，不再手写**：这两个 gate 的路径本来就写在
`spw-manifest.json` 里。让 workflow 用一行 python 从 manifest 取出
`command` 的脚本路径再执行，本地和 CI 从此不可能写岔。手写路径是这类 bug
的根因，改对一次不如改对一辈子。

**第三步——加一步前置自检**：在跑 gate 之前，一行 python 断言
`tools/spw-gates/*.py` 里被 manifest 点名的脚本都存在（复用
WO-20261004-0082 的同一判据），不存在就直接红，并报出缺哪个。

## 验收

不能只靠"本地把路径改对了"。必须满足：

1. 本地 `git stash -u` 无关文件后，在**干净检出**（`git archive HEAD` 解出来的
   临时目录）里跑这两条命令，RC=0。
2. word-level 反证：把路径改回 `..\tools\...` 后，在同一个干净检出里跑，
   必须 RC≠0——证明这条断言真的能抓住路径错，而不是靠环境放过。
3. 反证同样要在**干净检出**里做，不能在主工作树里做——主工作树里
   `..\tools\` 恰好存在，会给出假绿灯。

  即令 step 失败），**不需要改**，别顺手重构。
