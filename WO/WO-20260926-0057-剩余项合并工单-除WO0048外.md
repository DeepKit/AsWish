### 1.1 · `.tsx` 等 UI 扩展名导致项目类型识别不出来（出处 WO-0054，P2）

**已核实的事实**（非推测）：
`TAsWishScanService` 把 `.tsx` 放进 `UI_EXTS`，`.tsx` 文件归 `fcUI`；
而 `DetectProjectType` 只看 `fcCode`。后果两条：

1. 只有 `.tsx`、没有 `.ts` 的 React 项目，`CategoryCount(fcCode) = 0`，
   `DetectProjectType` 返回 `'unknown'`——一个 React 项目没被认出来。
2. `HasAnyExt(LCodeFiles, ['.ts', '.tsx'])` 的 `.tsx` 半边**永远不可能命中**，
   是死分支，留着会让人误以为 TSX 已被覆盖。

**路线已定：B**（沿用 WO-0054 §4 的默认路线，无人异议）。理由：分类表影响的是
页面统计口径，能不动就不动；项目类型是纯元数据（`DetectProjectType` 注释自述
"displayed and written into project.yaml, nothing branches on it"），
放大它的检测面不改变任何统计口径。

做法：把 React 检查的输入从"`fcCode` 文件"改成"`fcCode` 文件 +
`UI_EXTS` 白名单里的文件"，**只对 `['.ts', '.tsx', '.jsx']` 生效**，
不把 `.html` / `.xaml` / `.qml` 算成 React 源码。

**验收**
1. `tests/Test.AsWish.Scan.pas` 的 `TsxOnlyProject_IsNotRecognisedAsCode`
   期望值从 `'unknown'` 改为 `'web_react'`，**先亲眼看过它转红再改实现**
   （当前它在 `24827d2` 是通过的，即钉住的是错误行为）。
2. 现有 7 条 `TScanProjectTypeTests` 全部仍通过，不因放宽检测面而翻转。
3. `DetectProjectType` 注释里写明为什么只覆盖到 `.jsx` 而不含
   `.vue` / `.svelte` / `.astro`（保留在 `UI_EXTS` 里但不参与 React 判定）。
4. 全量测试不回退（当前基线 322/322），三构建 exit 0。

### 1.2 · Inspector 提交与 HB Deck 两个入口状态不同源（出处 WO-0049，P1）

**已核实的事实**：`PerformInspectorSubmit` 直调 `Controller.SubmitUserIntent`，
**不经** `FHBBinding.ProcessHbAction`，所以 Inspector 提交的 ChangeSet
**不进 deck 的 `LastChangeSetId`**。Esc/Enter/🚩 三个键盘动作只能命中
"经键盘 9 或候选流"产生的 ChangeSet。自动化里用键盘 9 等价路径绕过，
真实用户路径本身可用，但**两个入口的状态不是同一个来源**——
这是会在某天变成真 bug 的结构问题，不是已经坏的功能。

**验收**
1. 收敛为一个入口：Inspector 提交也走 `FHBBinding.ProcessHbAction`，
   或抽出共用的一段，让两个路径写同一个 `LastChangeSetId`。选哪种由承接方定，
   但**必须在代码注释里写明为什么这样选**。
2. 新增测试钉住：两条入口各提交一次，`LastChangeSetId` 都被更新为各自的 id。
   **先看它转红再改。**
3. 回归：`Test.AsWish.Controller.pas` 的 deck 相关用例全绿；`--gui-verify` 的
   Inspector 步骤仍 PASS。

### 1.3 · 窗口截图抓不到 CheckBox 勾选态（出处 WO-0049 / WO-0050，P1）

**已核实的事实**：`SaveWindowScreenshot` 以 `TCustomForm.GetFormImage`
（`Vcl.Forms.pas:9733`，内部走 `PaintTo`）为底，而 `PaintTo` **不反映
`TCheckBox` 的实时勾选状态**——实测 `Checked=True` 时的窗口截图与
`Checked=False` 的旧控件截图**字节相同**。故勾选态的可视证据只能靠独立的
控件捕获（`SaveControlImage` / `CaptureControlBitmap`）而非窗口截图。

**本单要的不是重写截图**，是把这条约束变成**别人改不动的**东西：

**验收**
1. 定义一个明确的枚举或布尔（例：`TCaptureMode` / `ACanReflectState`），
   标注每个捕获路径**能不能**反映控件实时状态，禁止再用"看起来像截图"的
   路径产出"证明勾选态"的证据。
2. 新增测试钉住：同一个 CheckBox，`Checked=True` 与 `Checked=False`
   的**窗口截图字节相同**（即证明确实抓不到，而不是偶然抓到了），
   而**控件捕获字节不同**。**先看它转红再改。**
3. `--gui-verify` 的 `[CAPTURE-WARN]` 数为 0，证据图扩展名与魔数一致
   （沿用 WO-0050 验收总纲）。
