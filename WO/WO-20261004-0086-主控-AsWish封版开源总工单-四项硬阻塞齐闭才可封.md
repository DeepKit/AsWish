## 一、四项硬阻塞（证据均已实跑，下游无需重新取证，但须复核）

### 阻塞 A · 要发出去的快照比本机旧一整个工单段

```text
$ git status --porcelain | wc -l
58
$ git log -1 --format='%h %ad %s' --date=short

```

**最后一次提交停在 WO-0070。** WO-0071 至 WO-0081 共十一张工单的成果——
gui-verify DOM 回收、截图黑屏内容守卫、fixture 幸存与验收测量点整改、
`gui-verify-progress.txt` 截断失败 fail-closed——**全部不在 HEAD 里**。
`git archive HEAD` 出去的那份（实测 225 个文件）比本机旧得多。
**你以为测过的东西，不在即将发布的包里。**

### 阻塞 B · 快照自带残缺：一道必需门禁的脚本根本没进版本库

`gate_gui_verify_smoke.py` 是 `??` 未跟踪。它守的正是 WO-0073/0074 那一族

".workbuddy/", ".AsWish/", ".ai-workbench/"]` 排除不该出去的，
**从没回头问过"manifest 点名的每道 required 门禁，脚本是否都在导出清单里"**。
少一道门禁的导出和齐装的导出，它一律判 PASS。

### 阻塞 C · CI 承诺书写错路径，克隆首跑即红

`.github/workflows/build.yml:38-45`：

```yaml
      - name: Deterministic gates (vendored-upstream drift / open-source export)
        run: |
          python -X utf8 ..\tools\spw-gates\gate_ehai_vendor_drift.py
          if errorlevel 1 exit /b 1
          python -X utf8 ..\tools\spw-gates\gate_open_source_build.py
          if errorlevel 1 exit /b 1
```

该 step **无 `working-directory`**，Actions 的 `run` 默认在检出根执行，
于是解释器找的是 `<repo>/../tools/spw-gates/`——**检出目录的上一级，仓库外面**。
干净克隆里该位置不存在，python 直接以"系统找不到指定的路径"退出。
本机能跑通只因本机恰好有平级目录结构，**属本地巧合，不是正确路径**。
脚本真实位置在 `tools/spw-gates/`（就在仓库根下）。

### 阻塞 D · 一条命令即外泄（不可逆，必须最先修）

**忽略清单没盖住**：`.gitignore` 有 `.claude/`、`dogfood_*/`、`scratch_*/` 等，
但**没有** `.AsWish/`、`.ai-workbench/`、`_repro/`、`_audit_out.txt`、
`_audit_err.txt`、`err_file`、`out_file`。

**内部治理材料确实躺在未忽略区**：`.AsWish/` 下 58 个文件，含内部治理标记
（`主控`/`开发AI`/`BetterCiv`）的实 grep 命中 **12 个**——`docs-summary.yaml`、
`evidence/implementation-evidence.yaml`、`evidence/source-evidence.yaml`、
`html/` 下 4 个、`scan-report.yaml`、`snapshots/` 下 3 个、`trees/function-tree.yaml`。

**假绿灯陷阱（最阴的一处）**：

```text
$ git check-ignore -v .AsWish/
.AsWish/.gitignore:8:	.AsWish/     ← 看起来"已忽略"，会骗过人
```

但那份嵌套 `.gitignore` 只盖住 `snapshots/`、`html/` 等重目录，
`commons/lesson-000*.yaml`、`decisions/`、`evidence/`、`docs-summary.yaml` 全没盖住。
换 `git status --untracked-files=all -- .AsWish/` 一跑：**24 个未忽略文件**。

**决定性取证**：

```text
$ git add -A --dry-run | grep -cE "\.AsWish|\.ai-workbench"
50
```

**50 个文件会被扫进公开仓库索引，含那 12 个带内部标记的。**
这不是假设，是 dry-run 已经演出来的后果。

## 二、执行阶段（顺序即依赖，不得调换）

### 阶段 0 · 堵外泄（工具链维护AI，最优先，独立成提交）

1. 补 `.gitignore`：加 `.AsWish/`、`.ai-workbench/`、`_repro/`、
   `_audit_out.txt`、`_audit_err.txt`、`err_file`、`out_file`，
   注明三者与 `WO/` 同属"不进公开仓库"一类。
2. 新增 `tools/spw-gates/gate_external_boundary.py`，两项断言任一命中即 RC≠0：
   - 路径命中 `REQUIRED_EXPORT_IGNORE` 同源黑名单（防漏加忽略）；
   - 内容含内部治理标记（`主控`、`开发AI`、`BetterCiv`、`BCW`、`工单`、
     `WorkBuddy`），并报出文件名与命中词。
3. **历史自查**：`git rev-list --objects --all` + `git cat-file` 全历史 blob 扫描，
   给出明确结论"干净 / 不干净"。**若曾进过提交历史，本单升级并停下报主控**
   （改历史不可逆，须老板裁定），不得自行 `filter-branch`。
4. 接入：新门禁加进 `spw-manifest.json` 的 required，并跑通 CI workflow
   （与阶段 2 第 2 步同一处）。

### 阶段 1 · 让快照自足（工具链维护AI）

1. 把 `tools/spw-gates/gate_gui_verify_smoke.py` 纳入版本控制
   （登记动作，非新代码），`spw-manifest.json` 的 required 随之补齐
   `H3.gui-verify-smoke`。
2. **给 `gate_open_source_build.py` 加完整性校验**：生成导出清单后读
   `spw-manifest.json`，对每个 `required: true` 的 gate，从其 `command`
   解析出 `.py` 脚本路径，逐一断言该路径在导出清单中；缺失即非零退出并
   报出 gate_id 与脚本。
3. **加反向断言**：工作树 `spw-manifest.json` 与
   `git show HEAD:spw-manifest.json` 的 required 集合必须相同，否则非零退出。
   这一条防"提交时手改清单把门禁悄悄删掉"。
4. 修 CI 路径：把 `build.yml` 两处 `..\tools\spw-gates\` 改为 `tools\spw-gates\`，
   补 `working-directory: ${{ github.workspace }}` 消除隐式默认值。
5. **路径改为从清单推导，不再手写**：用一行 python 从 `spw-manifest.json` 取
   `command` 的脚本路径再执行。手写路径是阻塞 C 的根因——改对一次不如改对一辈子。
6. **加一步 CI 前置自检**：跑 gate 前断言 manifest 点名的脚本都存在，
   （与第 2 步同一判据），不存在即红并报出缺哪个。

### 阶段 2 · 分主题提交（开发AI）

**本阶段全程禁用 `git add -A`。** 该命令在当前仓库状态下会一次性把 50 个

2. `tools/spw-gates/` + `spw-manifest.json`（归阶段 1 的成果）；
3. `tools/gui-verify-fixture/` 的 fixture 与生成脚本（WO-0069/0072）；
4. 测试（`tests/Test.AsWish.GUIDecisions.pas` 等）；
5. 治理与工具文档（`.github/`、`tools/spw-gates/`、`WO/ACCEPTANCE-HARNESS-RULES.md`）。

### 阶段 3 · CHANGELOG 补到当前版本（开发AI）
