## 一、缺陷本体

### 1.1 实测：两条 release blocker 都是"空"，不是"错"

```
py -3 -X utf8 <BetterCiv>/skills/spw/scripts/spw.py verify --evidence spw-evidence-c5324ed.json
→ ok=true, errors=[], warnings=[]
→ release_blockers = [
     "heterogeneous observer coverage 0/2 is not satisfied by the observations actually recorded",
     "certification.status='withheld' is not an issued certificate"
  ]
→ acceptable_for_release = false
```

证据包内部实况：

| 字段 | 值 |
|---|---|
| `external_observations` | `[]` |
| `observer_seat_outcomes` | `[]` |
| `valid_observer_families` | `[]` |
| `required_observer_families` | `2` |
| `h5_observation_verdict` | `null` |
| `certification.status` | `"withheld"`，`reason=H5_HETEROGENEOUS_OBSERVATION_UNAVAILABLE` |
| `execution_status` | `"degraded"`，`release_ready=false` |

### 1.2 根因：观测席位入口根本不存在

`tools/spw-evidence/generate_evidence.py:97` 原文：

```python
# Without live external GLM/Stepfun observer seats, record as degraded & withheld
```

`external_observations` / `observer_seat_outcomes` / `valid_observer_families` 三个字段
**全是硬编码空数组**，没有任何读取外部观测的代码路径。
也就是说：无论跑多少次门禁，`coverage` 永远停在 0/2，`certification.status` 永远停在
`withheld`，`acceptable_for_release` 永远是 `false`。**封不了版，且不会自己好转。**

### 1.3 重要澄清：这不是缺陷，是正确行为

本单**不是**要控告下游造假。把"没有观测"如实写成"degraded/withheld"，
恰恰是 WO-0091 之后期望的状态——比 WO-0086 那次"把没跑的门禁写成 PASS"高一个数量级。
本单要修的是**入口缺失**：系统想诚实时诚实地了，但没有给"真的去观测"留门。

## 二、执行阶段

### 阶段 1：打开真实观测的注入入口（必做）

`generate_evidence.py` 增加一个**只读观测席位输入文件**的读取路径，
不得保留任何硬编码空数组：

- 输入路径由 manifest（如 `runtime_contract.observer_input`）指定，缺省 `<repo>/spw-observations.json`；
- 每条观测记录必须自带：`family`（模型家族标识）、`model_id`、`observer_id`、
  `observed_at`（ISO8601）、`subject_sha256`（被观测的证据包/工件哈希）、
  `findings[]`（含 severity / 位置 / 描述）、`response_digest`（模型原始回复的哈希）。
- `valid_observer_families` 由程序从记录中**实算**去重，不接受外部声明。

### 阶段 2：防自签（必做，本条是硬门）

`spw-observations.json` 与 `h4_approvers.json` 是同性质文件——
一旦允许手工填写，就复刻了 WO-0091 的"自封批准人"缺陷。因此：

1. 观测记录的 `family` 必须在 manifest 的 `observer_families` 白名单内，
   未登记家族 → `[HIGH] unregistered observer family` → 证据包 `release_ready=false`；
2. **同一 `family` 计一次**，`2` 必须来自两个不同家族，同家族两个变体不算
   （与 Amy 多模型纪律同源：同一家族不同变体不算两个独立 LLM）；
3. `subject_sha256` 必须与本次证据包的 `subject.sha256` 一致，
   否则视为"观测的不是这个版本" → 拒绝；
4. 输入文件本身纳入 H4 完整性哈希钉死（参照 WO-0092 的方案），
   改动必须动 manifest；
5. `generate_evidence.py` 在 `release_ready=true` 前必须把上述校验结果
   一并写入证据包 `pending_h5_findings` / `h5_observation_verdict`，不许静默通过。

### 阶段 3：真的跑两次只读观测（必做，本单的实质工作量）

阶段 1-2 只是修门，**门修好了不等于封版**。还必须真实执行：

- 席位一：主控（本会话模型）对 HEAD 做只读复核，产出 `findings[]`；
- 席位二：经 WiseGateway / 现有多 LLM 通道调用**另一个模型家族**
  （GLM / StepFun / Kimi / Qwen 任选其一，不得与席位一同家族）做独立只读复核；
- 两个席位的原始回复先落盘到 `WO/evidence/h5/`，再压缩为结构化 `findings[]` 注入；
- 若某家族不可用 → **如实降级为 withheld，不得用同家族变体凑数，更不得造假记录**。

### 阶段 4：README 与门禁自报家门

- `tools/spw-evidence/README.md` 写明：观测席位输入文件在哪、谁能新增、
  被封版软件必须满足什么条件，以及"H5 degraded/withheld 是正常且诚实的状态"；
- 证据包生成后必须打印 `coverage=X/2` 与 `certification=<status>` 到 stdout，
  不允许只落 JSON（参照 WO-0077 门禁自报家门）。
