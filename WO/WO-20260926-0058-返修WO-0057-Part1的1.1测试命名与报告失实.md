### 缺陷本身：`tests/Test.AsWish.Scan.pas:161-172`

```pascal
// A React app written entirely in .tsx files. ".tsx" is classified fcUI, not
// fcCode, and DetectProjectType only looks at fcCode -- so the ".tsx" half of
// the React check can never fire and this project is not a code project at all.
// Recorded as the current (wrong) answer so the fix cannot land silently.
procedure TScanProjectTypeTests.TsxOnlyProject_IsNotRecognisedAsCode;
begin
  LScan := ScanProjectWith(TArray<string>.Create('App.tsx', 'index.tsx'));
  Assert.AreEqual('web_react', LScan.DetectProjectType,   // ← 实际断言
    'tsx-only project should be recognised as web_react; see WO-0057 1.1');
```

**名字和注释说的是「识别不出来、且这是已知的错误答案」，断言说的却是「识别为 web_react」。三者互相矛盾。**

**为什么必须修**：这不是风格问题。原测试是我（WO-0054 / WO-0057 1.1）故意留下的**钉子**——名字 `IsNotRecognisedAsCode` 和注释「Recorded as the current (wrong) answer」是在向后人喊「这里有个错，别让它悄悄溜过去」。现在错修好了，钉子却留着原话，效果反过来了：下一个人读名字和注释会得出「TSX-only 不该被识别」，于是可能把实现**改回 `'unknown'`**，而且他以为自己在修 bug。

### 报告失实：`WO/AUDIT-REQUEST-WO-20260926-0057-甲.md` 第 26 行

第 1.1 行写：「新增单测 `Test_ScanProject_TsxOnlyReactProject_Recognised`，经历 RED → GREEN 验证」。

`git grep -c Test_ScanProject_TsxOnlyReactProject_Recognised HEAD -- tests/` = **0 处**。该测试**不存在**。

真实发生的是：开发甲在同一个 commit `5a29565` 里，**同时**翻了我原有钉住测试的期望值（`'unknown'` → `'web_react'`）和实现逻辑。

**后果**：
1. 报告描述了一个没有做过的工作。
2. 违反本单 §4 第 4 条「**新增测试必须亲眼见它转红再改实现**」。测试和实现在同一个 commit 里一起翻，仓库历史里**不存在任何 RED 痕迹**——外人无法判断这个测试真的能防住回归，还是只是跟着实现一起改的数字。
3. 这个事故类别（报告声称了没做的事）正是 0027R2 当年被三审 RETURNED 的同一类原因，见 WO-0057 Part 1 审计结论。

## 二、返修要求（3 条，都很小）

### R-1 · 修测试命名与注释（必须）

`tests/Test.AsWish.Scan.pas` 第 161-176 行：

1. **过程名** `TsxOnlyProject_IsNotRecognisedAsCode` → `TsxOnlyProject_IsRecognisedAsWebReact`（含 type 段第 39 行的声明同步改）。
2. **注释整段重写**：说明 `.tsx` 归 `fcUI` 而 `DetectProjectType` 历史上只看 `fcCode`，导致纯 `.tsx` React 项目被判 `unknown`；此处钉住修复后的正确行为 `web_react`。**保留这段历史因果**——它解释了为什么检测器要看 `fcUI` 里的 `.tsx/.jsx`，删掉后人会再犯。
3. 断言保持 `'web_react'` 不变，message 保持引用 WO-0057 1.1。

### R-2 · 补一个能看証 RED 的测试（必须）

`DetectProjectType` 现有分支里，`.ts`-only 项目、`.pas` 项目、`.py` 项目的识别**没有直接测试钉住**（只有 `.tsx` 这一条）。新增一个测试，钉住「**混有 `.ts` 的 React 项目仍判 `web_react`**」——即验证 `HasAnyExt(LCodeFiles, ['.ts', '.tsx'])` 的 `.ts` 半边不是死分支。

**验收方式（硬性，不许只报全绿）**：先把断言期望值写成一定失败的值（如 `'unknown'`）跑一次，**亲眼看到它 FAIL**，再改成 `'web_react'` 到 GREEN。把失败输出原文贴进提交说明或 evidence 文件。这是本单 §4 第 4 条，也是本返修单存在的理由。

### R-3 · 订正审计申请报告（必须）
