## 〇、一句话

门禁台账与日志的落盘路径，在**写入方和读取方各硬编码了一次**。
这次搬迁（WO-0098）要同步改 4 个调用点才对齐；**漏改任何一个的后果是
"写者写新路径、读者读旧路径"，而且这种分裂不会报错，只会静默地产出错误判定。**

## 一、缺陷本体（实测两处定义）

```
tools/spw-gates/run_all_gates.py:26        GATE_RUN_DIR = GATES_DIR / "gate-run"
tools/spw-evidence/generate_evidence.py:20 GATE_RUN_DIR = ROOT / "tools" / "spw-gates" / "gate-run"
```

连路径拼接的写法都不一样（一个基于 `GATES_DIR`，一个从 `ROOT` 全量拼出），
只是**当前恰好指向同一目录**。分派到具体调用点：

| 脚本 | 行 | 用途 |
|---|---|---|
| `run_all_gates.py` | 81 | 逐门 stdout 日志落盘 |
| `run_all_gates.py` | 237 | 台账 `gate_run_results.json` 落盘 |
| `generate_evidence.py` | 457 | 读台账 |
| `generate_evidence.py` | 505 | 读逐门 stdout 日志 |

**两个脚本互相 import 不了对方**（一个是门禁运行器，一个是证据生成器），
所以现状只能用"各自定义"绕过去。WO-0098 的搬迁即因此牵动 4 个点。

### 1.1 为什么会静默

`generate_evidence.py:457-462` 对台账缺失是**硬失败**（`RuntimeError` → RC=1），
这一条有牙。但日志那条不是——`generate_evidence.py:505-507` 同样是
`if not log_file.is_file(): raise`，也有牙。

真正静默的场景是**部分搬迁**：比如台账读了新路径、日志还读旧路径，或反之。
此时两条检查各自通过/各自失败的组合取决于改了哪一半，**没有任何一处
会对比"写入方说的路径"和"读取方说的路径"是否同一个**。

### 1.2 风险不在今天，在下一次

今天是主控手工双向核对的（`find . -name gate_run_results.json` 只剩一份）。
但下一次动这段代码的人——无论是我方还是换人维护——没有这个 guard，
只能靠"我记得要改两处"。这正是 WO-0099 §1.3 记录的
**"9 门显式、1 门启发式，极易误判这里也是显式的"同一个维护陷阱**，
只是换到了路径层。

## 二、执行阶段

### 阶段 1：路径常量化到单一真值（必做）

把 `GATE_RUN_DIR` 提为**唯一定义**。`tools/spw-gates/gate_lib.py` 是现成归属：
两个脚本**都已经** `from gate_lib import ...`，不新增 import 关系。

- `gate_lib.py` 定义 `GATE_RUN_DIR`（含 `ROOT`）；
- `run_all_gates.py` 与 `generate_evidence.py` **删除本地定义，改为 import**；
- 保留 `gate-run` 这个目录名不变（WO-0098 已把它钉进受控路径，
  本单不得再改位置，避免又触发一次外部面扫描联动）。

### 阶段 2：加一条自洽断言（必做）

`generate_evidence.py` 启动时**同时向写入方求证**：调用
`run_all_gates` 模块（import，不执行）取出它的 `GATE_RUN_DIR`，
与本地 import 来的值比对，不一致即 `RuntimeError` → RC=1。

这一条才是本单的真正价值：它把"记得改两处"变成"改漏了就响"。
**注意是 import 取值，不是 subprocess 调用**——不得为了拿一个路径去跑门禁。

### 阶段 3：README 记录归属（必做）

`tools/spw-gates/README.md` 写明：门禁凭据路径的唯一定义在 `gate_lib.py`，
下游不得在别处另定义。
