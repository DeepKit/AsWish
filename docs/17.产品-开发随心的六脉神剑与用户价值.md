## 一、一个哲学更正

在差异一元论里：

> **差异不是异常，差异是存在与变化的常态。**

因此 AsWish **不是**「管理错误、避免错误、消灭错误」的工具。

而是：

> **让人在差异恒常存在的世界里，可以随心开发，并且始终能够看见、理解、调整自己的所作所为。**

这是本次升级改对的根子：过去资料里残留的「防错 / 找偏差 / 修错误」语言，退居为次要；「差异是常态、判断权在人」升为产品哲学的主干。

---

## 二、产品一句话

> **AsWish = 开发随心的六脉神剑。**

不是「六道防线」，是「六脉贯通」——让心、眼、结构、机器、现实之间保持通畅。

---

## 三、六脉：六种随心开发能力（不是六个功能）

| 六脉 | 核心问题 | 随心开发中的作用 |
|---|---|---|
| **① 显影** | 我究竟想什么？ | 心有所想，使之显形；不要求一开始就说标准 |
| **② 对齐** | 我看到的是我要的吗？ | 心里想的与眼前看到的，是不是同一个东西 |
| **③ 结构化** | 怎么让机器准确承接？ | 让已确认的心意获得可被机器承接的形体 |
| **④ 差异** | 现实与我所想哪里不同？ | 看见自然发生的变化，不预设对错 |
| **⑤ 调整** | 我要不要向哪里变化？ | 沿着差异继续演化，直到此刻想要的状态 |
| **⑥ 积累** | 这次经历留下什么？ | 让这一次的路径，成为下一次的剑 |

它不是「发现错误 → 修错误」，而是：

```text
我想怎么做 → 让我看见我想的是什么 → 让我确认我看到的是什么
→ 让机器准确承接我确认的东西 → 交给 AI 去开发（外部 Agent）
→ 看看实际世界发生了什么差异 → 我再决定往哪里调整
→ 把这一路走过的东西留下来
```

## 四、三层投影（防误读：六脉不是第二套流程）

六脉**不新增任何实体 / 状态 / 流程**，它是既有工程链的**叙事投影**：

```text
六脉  = 哲学 / 对外叙事层   「人怎么随心开发」
七环  = 产品闭环层          「产品闭环有几环」（见 01.产品 §四）
14 段 = 工程实施层          「任务按什么顺序做」（见 07.工程 §八）
```

三者是**同一件事的三种投影**，不是三个并列流程。映射如下：

| 六脉 | 对应工程环节 | 事实等级 |
|---|---|---|
| ① 显影 | Problem Manifestation | FACT |
| ② 对齐 | Visual Baseline | FACT（0028） |
| ③ 结构化 | Spec Construction · Confirmed Understanding | FACT |
| ④ 差异 | Difference | FACT（作用域见下） |
| ⑤ 调整 | Human Judgment + Revision | FACT（作用域见下） |
| ⑥ 积累 | 经验回流（Difference Case） | VISION |

> **六脉能力正式等级（只有三种）**：**FACT** 代码与测试已证明 · **PLAN** 计划中 · **VISION** 长期愿景。全仓以「当前真实代码 + 通过测试 + 已定协议」为最高优先级。
>
> **等级口径裁定（不得混用）**：`DESIGN`（已确定设计）与 `HYPOTHESIS`（未验证假设）**不是六脉能力等级**，它们是**概念成熟度 / 研究状态标签**，只用于标注概念、上位提法与传播假设等「非能力项」（如本文 §五 Reality Visibility `[DESIGN]`、§七 Aha Moment `[HYPOTHESIS]`）。表述能力等级时，一律只用 `FACT / PLAN / VISION`。
>
> 能力范围一律通过 Scope / Boundary 注释表达，**不得新增 SCOPED FACT / PARTIAL FACT / ENGINEERING FACT / PRODUCT FACT 等第四种状态**。

### ④ 差异 · FACT Scope / Boundary（As of 2026-09-10）

可达（当前事实）：

```text
Accepted Baseline
→ Implementation Evidence / Result
→ Formal Difference Comparator
→ Difference Service → difference.yaml
→ Observable
→ Human Judgment
```

实证支撑：First Closed Loop v0 Structural Difference；Baseline vs Implementation Evidence/Result；Missing / Extra / Changed；Content / Relation Difference；正式 Difference Service 与 Platform Comparator 扩展路径；VCL 受控 Profile 下 `left-of / right-of` L2 Difference 已有真实 Dogfood Evidence；另有有限 L3 style / appearance Evidence。

**不得被扩大解释为**：Pixel Diff（全像素视觉比较）· 所有布局/样式语义均已覆盖 · 所有 VCL 控件均已覆盖 · OwnerDraw / Custom Paint、VCL Styles、第三方控件全覆盖 · FMX / Web / 所有平台全覆盖 · 所有语言与框架全覆盖 · 自动 Difference 归因 · 自动判断 Difference 是 Error · 自动修复 Difference。

> 局部平台证据不得泛化为 Universal Capability。**FACT ≠ Universal Coverage。**

### ⑤ 调整 · FACT Scope / Boundary（As of 2026-09-10）

正式链路（当前事实）：

```text
Difference
→ Human Judgment
→ Decision
→ Revision / Evolution
→ New State
→ Re-verification
```

判断出口：Acceptable / No important → **Evolution** → New Baseline → Lineage；Unacceptable → **Revision** → 回到 Human Intent → Rebuild → Re-verification；Unresolved → 保持未决，等待更多 Evidence / Human 判断。

实证支撑（最新已确认）：`B-0003 ParentBaseline = B-0002`；0027 系列 First Closed Loop 最终审计 **APPROVED / CLOSED**，四项硬标准达成。Evolution 分支 Dogfood Evidence 当前最直接；Revision 分支已具备正式工程实现与产品可达性——**但不得对外夸大为「Revision / Evolution 两分支都已有大量真实用户案例」。**

**⑤ FACT 绝对不等于**：AI 自动修复 / 自动纠错 / 自动调整直到测试通过 / 自动决定 Difference 是否重要 / 自动接受 Difference / 自动覆盖 Human Decision / 自动回滚一切变化。

> **Difference ≠ Error**；**AsWish ≠ 自动纠错系统**。

## 五、Reality Visibility：上位概念（[DESIGN]）

「看见差异」不是 AsWish 价值的全部，更上位的概念是 **Reality Visibility（现实可见性）**：

> **让开发者始终知道自己原来想构建什么，以及现实中现在实际变成了什么。**

Difference 是 Reality Visibility 的重要机制之一，但不是全部。两个结果**同样有价值**：

| 结果 | 开发者获得 | 性质 |
|---|---|---|
| Difference > 0 | 看见「实际做的」与「确认的」之间的变化 | 差异信息，交由 Human Judgment |
| Difference = 0 | **Confidence**：「我知道现实与我确认的东西一致」 | 确信，同样是有价值的结果 |

> **Confidence ≠ 「保证没有 Bug」**。它只意味着「我知道现在发生了什么」。这是防错工具与 AsWish 的分水岭：防错工具在「没发现错误」时是白跑一趟，AsWish 在「没发现差异」时是获得确信。

工程落点：Reality Visibility 由 [`03.规范-可见判断与交互规范.md`](03.规范-可见判断与交互规范.md) 的 **VC-01 ~ VC-06** 六个 Visual Checkpoint 共同提供。它不是新实体，而是给既有可观察链一个上位名字。

## 六、用户为什么愿意用（价值在使用中体现）

用户不是为「防错」而来，而是在真实开发中，每一步都能感到「我能看见、我能理解、我能决定」：

1. **想说就说，不必先想清楚**。当你想说「这里感觉不太对」「我想让它像某某东西，但不是完全一样」时，AsWish 不要求你先说标准——它帮你**显影**，让你自己看见自己真正想表达的东西。
2. **所见即所想，而不是读 YAML**。你说「简单一点」，AsWish 把它变成能看的东西；你对它说「对，就是这个感觉」或「不要这个布局」——**对齐**在很早的时候就自然发生。
3. **机器承接的是你确认过的东西，不是你的只言片语**。你的心意经过显影、对齐之后，才被**结构化**成机器能承接的形体——减少的是人与机器之间无谓的来回，不是增加一道审批。
4. **开发完，看见发生了什么，而不是猜**。实际做出来的，与你确认过的，之间发生了什么变化，AsWish 把它**显现**出来——你不必去读代码猜机器到底做成了什么。
5. **差异出现，你可以说「我喜欢，不改」**。差异不等于错误，你可以接受、可以拒绝、可以往别处调——**调整**的主动权在你，不在「系统判定它错了」。
6. **走过的路，会成为下一把剑**（**VISION · 未来目标，非当前已交付能力**）。这是 AsWish 要达成的样子：你这次怎么想、怎么表达、怎么判断、中间发生了什么分叉、为什么又调整，将来都会留下来；下次不必从零开始，别人走过的路也能帮你提前看清前路。**当前（As of 2026-09-10）⑥ 积累仍为 VISION，尚未实现，不作为已交付价值承诺。**（①–⑤ 中，④⑤ 见上文 Scope / Boundary。）

> 补充：即使一次开发中 **Difference = 0**，你仍然获得了一个有价值的事实——**「我知道现实与我确认的东西一致」**（Confidence）。这是 AsWish 与防错工具的分水岭。

一句话：**使用 AsWish 的过程，就是「看见 → 理解 → 决定」不断循环的过程；价值不是宣传出来的，是在这个循环里被用户一步步用出来的。**

## 七、Aha Moment：传播的核心单位（[HYPOTHESIS]）

产品传播的关键不是「有多少功能」，而是**开发者第一次看到一个自己此前看不到的东西**。可能的 Aha Moment：

- AI 改了开发者没意识到的地方；
- AI 漏掉了开发者以为已经完成的东西；
- AI 的实现方式和原来想的不一样；
- AI 的不同实现反而比原设计更好；
- 自己原来的想法其实没有真正想清楚；
- 一个 Difference 改变了自己的判断。

> 这是**传播假设（HYPOTHESIS）**，尚未被真实用户实验验证。当前不虚构任何案例；只有真实使用产生的结果才能作为 Case。

## 八、「省钱省时省心」是结果，不是哲学

```text
开发随心
   ↓
六脉贯通
   ↓
减少无谓的信息损耗 → 减少不必要的来回 → 减少无意义 Token → 减少重复劳动
   ↓
省钱 / 省时 / 省心
```

「省钱省时省心」是**六脉贯通之后产生的现实收益**，是价值结果；「开发随心」才是产品哲学本身。**两个层次不得混淆**——尤其在对外的 README、官网、博客里，不得把「省钱」当作卖点，把哲学降级成促销文案。

## 九、两条边界（随心 ≠ 随便）

1. **随心 ≠ 随时改变 Canonical State**。心意可以自由变化（Conversation Surface：探索、联想、推翻、重新表达），但只有正式的人类决定才进入确定状态（Decision Surface：此刻我决定）。这是 [`03.规范-可见判断与交互规范.md`](03.规范-可见判断与交互规范.md) 分册二的 Dual-Surface 已经工程化的边界。
2. **差异是常态，但「Unacceptable」仍是合法判断**。人可以自由地说「这个差异我不要」。哲学上「差异是常态」，不取消「人可以拒绝某个差异」这个权利。
