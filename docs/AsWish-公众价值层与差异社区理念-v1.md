# AsWish 差异社区与公共经验库理念 (Difference Commons)

> **版本**：v1.1
> **状态**：理念冻结（重点重构社区价值体系）
> **时间**：2026-08-31

---

## 一、 社区的本质：非传统的内容平台

AsWish 最终建立的，不是一个充斥着“用户、帖子、点赞、积分”的传统交流社区，而是一个**不断积累人机协作差异知识的公共设施（Public Facility）**。

在差异一元论的视角下，软件开发中意图与实现的错位不是“Error”，而是“Difference”。因此，AsWish 的社区被称为 **Difference Commons（差异共同经验库）**。

- **GitHub**：共同积累代码解决方案。
- **Wikipedia**：共同积累人类客观知识。
- **AsWish Commons**：共同积累“人类与 AI 协作时真实发生过的语义分叉与演化轨迹”。

它记录的不是“正确答案大全”，而是：**“过去的人类，曾在这里与机器发生过怎样的分歧，最终又选择了哪条道路。”**

---

## 二、 核心价值观与社区文化

### 1. 社区行为准则
> **Use privately. Learn collectively. Contribute optionally. Benefit publicly.**
> （私下使用，集体学习，自愿贡献，公共受益）

AsWish 坚决拒绝以“强制贡献”或“诱导上传”来换取理论数据。贡献必须是使用过程的自然出口，而非额外任务。

### 2. 社区文化凝练
传统开源文化的骄傲是：“Show me your code.”
AsWish 社区将形成的新文化是：“**Show me where your intent diverged.**（让我看看你曾在哪里面对过分叉）”

它的终极人文关怀在于：
> **Every contribution becomes someone else's smoother path.**
> （你留下的一次分叉路标，将成为别人开发随心的一段通途。）

## 三、 公共资产的三级演化形态

公共知识绝不能是松散的聊天记录，必须是真实发生过、并经过人类确认的人机理解分叉。社区资产遵循严格的三级演化：

### Level 1: Difference Case（差异轨迹）
公共资产的最小原子。它必须包含真实的、完整的演化闭环：
- **Human Intent**（人类初始意图）
- **AI Interpretation**（机器最初的演化理解）
- **Human Decision / Adjustment**（人类的最终裁断与调整）
- **Observed Difference**（两者之间的实质差异点）
**原则**：未经验证的“疑似差异”只允许私有保存；只有经过 Human 确认修正的真实轨迹，才具备进入公共库的资格。

**协议同构性**：Difference Case **不是新的孤立数据结构**，而是从本地 `.AsWish/` 标准协议（`candidate-intent.yaml` + `change-set.yaml` + `requirement-decisions.yaml` + `difference.yaml`）中经脱敏后直接剪裁导出的可验证凭证切片（`difference.yaml` 随 0027G 落地）。社区层不得另立一套平行 Case 格式。

### Level 2: Difference Pattern（差异模式）
多个独立的 Case 经过社区验证、聚合与抽象后，提炼出的共同模式。
- **例如**：Case 是某人发现 AI 把“禁用用户”理解成了“DELETE 语句”；Pattern 则是社区归纳出的『状态封存与级联删除在特定语境下的固有歧义』。

### Level 3: Divergence Prism（差异棱镜 · 前置显影知识）
高度成熟的 Pattern，成为帮助后来者提前发现类似分叉的结构化知识。
它被用于 **上下文回流（Contextual Retrieval）**，在后人的开发流中充当“差异棱镜”，提前显影出潜在的分歧点，交由人类决断。

## 四、 开源级声誉与贡献者机制

AsWish 坚决反对把公共资产变成“积分打卡任务”（如“贡献一个案例奖励 10 积分”），这会严重污染资产质量。贡献的动力必须回归**开源互惠精神**。

### 1. 摒弃积分，采用 Git 式溯源
借鉴 GitHub 的声誉系统，每一次提交的 Difference Case 都有严格的元数据：
- Case ID
- Contributor（允许署名或匿名）
- Timestamp
- 关联的 Pattern

### 2. 角色分化，而非等级划分
社区不设“活跃度等级”，而是根据对公共资产的实质干预建立角色：
- **Case Contributor**（轨迹贡献者）
- **Pattern Contributor**（模式归纳者）
- **Validation Contributor**（验证者）
- **Commons Maintainer**（公共库维护者）

### 3. 核心价值指标：Cases Reused（复用影响力）
衡量一个贡献者伟大与否的唯一标准，是他的经验**帮助过多少次后来的人机协作**。
- *普通社区反馈*：“感谢你的提交，获得 50 积分。”
- *AsWish 社区反馈*：“Alice，你贡献的 `[禁用与解绑歧义]` 轨迹，已累计帮助 637 位开发者提前显影了潜在分歧。”
这种直接的、开源式的影响力反馈，才是真正的社区驱动力。

## 五、 防污染与质量防御边界

开放的 Commons 必然面临失真案例、过度概括、个人特殊习惯甚至恶意提交。系统必须建立坚固的防御圈：

### 1. 从 Case 到 Pattern 的群体验证
- 一次提交（Submit）绝不能立即成为公共规则。
- **孤证不立**：一个人的一次差异只是 Case。只有当来自不同开发者、不同工程上下文的相似 Case 被反复观察到（Observed → Repeated → Corroborated），才能晋升为 Established Pattern。
- 公共知识的可信度来源于**真实的独立工程复现**，而非简单的投票。

### 2. 隐私与数据逻辑分离
贡献者拥有绝对的控制权：
- 可选状态：Private（私有）、Shared（小圈子共享）、Anonymous（匿名公开）、Public（署名公开）。
- 随时撤回权。但为了保护公共资产，一旦个人的 Case 参与熔炼成了公共的 Pattern，个人轨迹与公共知识将进行逻辑切断。即便用户销毁了自己的 Case 原始记录，已经凝结的公共 Pattern 依然存续，避免单点退出引发知识库坍塌。

### 3. 结构脱敏硬门禁（Sanitization-by-Design）
贡献的最大心理阻力不是匿名，而是害怕业务专有代码、API Key 或内部业务逻辑被附带上传。因此脱敏不能是上传时的手动检查，而必须是**离开本地前的结构级前置门禁**：
- **物理隔离 + AST 级脱敏**：Difference Case 在离开本地环境前，系统提供自动语法脱敏（剥离字面量、混淆专有命名、抹除密钥与 PII），只导出纯粹的语义分歧结构与拓扑差异。
- **目标**：确保「贡献分叉经验，零泄露业务资产」。

## 六、 AsWish Value Loop (差异社区价值飞轮)

基于上述理念，AsWish 的价值流转呈现为三大循环的叠加：

**① 个人随心循环**：
> 表达意图 → 差异自然出现 → 看见并调整差异 → 将经历沉淀为个人经验。

**② 社区互惠循环**：
> 贡献个人经验 → 丰富公共 Commons → 他人从中受益并持续贡献 → 自己在未来任务中获得更强大的差异显影能力。

**③ 理论实证循环**：
> 在无数真实世界、真实工程的分岔与修正中，沉淀出纯粹的人机协作演化数据，在不增加用户额外负担的前提下，为“As We Wish”与差异一元论提供持续、真实且开放的经验观察与证伪检验样本，使理论始终保持与真实工程世界互动演进的生命力。

这是一个完全自洽的生命体：
**“我因为别人贡献的经验，提前看清了前方的分叉路口；我把我探索过的分叉轨迹留下来，让世界上的其他人，也能更随心所欲地继续前行。”**

---

## 七、实施阶段纪律

Difference Commons 是**长期公共价值基础设施**。在当前阶段（First Closed Loop），**严禁过早开发复杂的云端社区服务端 / 后端 API**。

当前核心任务只有两个：

1. **确立 Case 的本地协议标准**（即 §三 的协议同构性：从 `.AsWish/` 标准协议脱敏剪裁导出 Case，不另立平行格式）；
2. **通过 AsWish 自身的 Dogfooding（自用自验）真实产出 `Case #0001 ~ #0010` 种子资产**。

在种子 Case 真实落地之前，本文件所述的一切社区机制（Commons、Pattern、差异棱镜、声誉体系）均属**愿景层，零实现**，不作为近期工程依据。
