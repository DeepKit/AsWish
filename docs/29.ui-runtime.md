# HB 运行时契约与控件生命周期规范 v1.0

> **文件编号**：29.ui-runtime (HB Runtime Contract & Lifecycle Specification)  
> **文档版本**：v1.0 (2026-09-04 官方工程基线版)  
> **适用范围**：`DeepBase` 核心库及下游所有基于 HB 人机行为基础设施构建的桌面与跨平台软件（`DeepCommerce 唤金`、`AsWish`、`DeepDsh`、`Assayer`、`DeepRW` 等）  
> **核心定位**：**确立 HB 控件从源码实例化、状态绑定、触点挂载、渲染管线到销毁治理的全生命周期确定性契约，为动态 UI 生成与人机交互状态流转提供强类型底层保障。**

## 1. 架构定位：HB Human Behavior Infrastructure 运行时层

在 DeepBase 生态中，HB 不仅仅是一套静态视觉组件库，而是**人机行为操作系统层**。

```
+-----------------------------------------------------------------------------------------------+
|  【产品业务层】(DeepCommerce 唤金 / AsWish / DeepRW / Assayer / DeepDsh)                       |
|  • 声明业务领域模型、客户关系状态、交易决策与动态表单生成需求                                     |
+-----------------------------------------------------------------------------------------------+
                                          │ 状态绑定与触点消费
                                          ▼
+-----------------------------------------------------------------------------------------------+
|  【HB Runtime Contract 运行时契约层】(本规范定义)                                              |
|  • 7 步生命周期流水线 (7-Step Lifecycle Pipeline)                                              |
|  • 四轴正交状态协议 (Visual / Business / Trust / Action)                                      |
|  • Design Token 版本治理与迁移协议 (Token Migration Protocol)                                  |
|  • 跨线程刷新与安全消息分发保障 (Thread Safety & Dispatch)                                      |
+-----------------------------------------------------------------------------------------------+
                                          │ 支撑与驱动
                                          ▼
+-----------------------------------------------------------------------------------------------+
|  【HB UI 控件与令牌底座】(Core / VCL / FMX)                                                   |
+-----------------------------------------------------------------------------------------------+
```

## 2. 控件生命周期统一模型（7-Step Lifecycle Pipeline）

所有 HB 体系控件（无论是静态放置还是运行时动态生成）必须严格遵循以下 **7 步标准生命周期**：

```
    [1. Create] ────── 实例化并分配基础资源
         ↓
  [2. BindToken] ───── 绑定当前主题 Token 实例，注入色彩/字号/间距
         ↓
  [3. BindState] ───── 绑定业务、信任与动作状态机
         ↓
[4. AttachTouchpoint] 挂载触点 ID 与四自转换契约 (UserState Before/After)
         ↓
    [5. Render] ────── 依托 GDI+ 缓存池与局部脏区进行确定性绘制 (禁止裸 Paint)
         ↓
   [6. Measure] ────── 触发 Telemetry 行为度量与触点事件输出
         ↓
   [7. Dispose] ────── 释放 GDI 句柄、注销 Theme 监听、持久化草稿 Snapshot
```

### 核心纪律红线
> [!CAUTION]
> **严禁裸 Paint**：禁止任何控件在未完成 `BindToken`、`BindState` 或 `AttachTouchpoint` 前直接调用 `Paint`。在 VCL `THbCustomControl` 基类中，必须采用模板方法模式（Template Method）确保生命周期顺序执行，杜绝因未绑定 Token 产生的高 DPI 闪烁或色值错乱。

## 3. 四轴正交状态协议（Four-Axis Orthogonal State Protocol）

为了彻底解耦 UI 视觉交互、业务领域逻辑、信任机制与用户动作意图，HB 确立**四轴正交状态模型**：

```
+-----------------------------------------------------------------------------------------------+
|                                四轴正交状态协议 (Four-Axis State)                             |
+--------------------------------+-------------------------------+------------------------------+
|       【1. 视觉交互态】        |        【2. 业务领域态】      |       【3. 信任评估态】      |
|        (Visual State)          |        (Business State)       |        (Trust State)         |
| • vsUnknown                    | • bsNormal                    | • tsUntrusted                |
| • vsCreated / vsReady          | • bsNeedFollowUp (需跟进)     | • tsLow                      |
| • vsFocused / vsSelected       | • bsDormant (沉睡唤醒)        | • tsMedium                   |
| • vsProcessing (流转中)        | • bsHighValue (高净值关注)    | • tsHigh (已建立强信任)      |
| • vsSuccess / vsWarning        | • bsFrozen (冷冻风险拦截)     | • tsVerified (官方验证)      |
| • vsError / vsDisposed         | • bsCustom(UserDefined)       |                              |
+--------------------------------+-------------------------------+------------------------------+
                                 |       【4. 动作意图态】       |
                                 |        (Action State)         |
                                 | • asIdle (静默待命)           |
                                 | • asWaitingConfirm (待拍板)   |
                                 | • asProcessing (执行中)       |
                                 | • asCommitted (已提交归档)    |
                                 | • asAborted (已放弃/退回)     |
                                 +-------------------------------+
```

### 映射与投影机制
- **UI 控件只负责映射视觉**：例如一个“唤金客户卡”，其 `VisualState = vsSelected`，`BusinessState = bsNeedFollowUp`，`TrustState = tsMedium`，`ActionState = asWaitingConfirm`。
- **业务内核独立演进**：业务状态的变化通过事件触发 UI 重绘，严禁将具体业务枚举硬编码进控件底层类库。

## 4. Design Token 版本治理协议（Token Migration Protocol）

随着全系产品（唤金、AsWish、DeepRW、Assayer）规模扩大，必须建立严格的 Token 版本迁移机制，**严防各业务侧偷偷魔改 Token 导致视觉系统碎片化**：

```
                 [Token v3.0] ──── 初始基准
                      │
                      │ 引入新语义色 (向下兼容)
                      ▼
                 [Token v3.1] ──── 标记部分过时字段为 Deprecated
                      │
                      │ 运行自动化迁移工具 (Token Migration Tool)
                      ▼
                 [Token v4.0] ──── 彻底移除过时色值，发布新主版本
```

### 治理规则
1. **SSOT 唯一真相源**：所有调色板与 Token 定义必须且只能存在于 `DeepBase.HB.Core.pas` 与 `DeepBase.HB.Palettes.pas`；
2. **严禁私有覆盖**：下游业务若需临时覆盖特定场景色彩，必须通过 `THbTheme.RegisterOverride` 显式注册并附带任务编号，禁止私自 Hack 控件绘制函数；
3. **废弃周期（Deprecation Policy）**：任何被淘汰的 Token 属性必须保留至少 2 个次版本（Minor Version）的警告过渡期，并通过 IDE Hint/Warning 引导迁移。

## 5. 跨线程安全与消息分发契约（Thread Safety & Dispatch）

1. **UI 线程守卫**：
   - 所有涉及 UI 重绘、Token 切换广播、触点状态跃迁的代码，必须在主线程执行；
   - 严禁在 UI 线程调用 `Sleep` 或同步阻塞的 RPC / SQL 操作；
2. **后台工作线程向 UI 派发标准**：
   - 严格禁止使用 `TThread.Queue`（容易在窗体销毁后引发悬挂指针 AV）；
   - **必须统一使用 `TThread.ForceQueue`**，并在闭包中校验控件 Handle 与 Assigned 守卫：
     ```pascal
     TThread.ForceQueue(nil, procedure
     begin
       if Assigned(TargetControl) and TargetControl.HandleAllocated then
         TargetControl.UpdateState(...);
     end);
     ```
3. **DPI 动态切换拦截（`WM_DPICHANGED`）**：
   - 基类捕获 DPI 变化消息后，依次调用 `BeforeDpiChange` $\rightarrow$ `RecalculateMetrics(NewPPI)` $\rightarrow$ `Invalidate`，确保多显示器拖拽零卡顿。
