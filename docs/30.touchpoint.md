## 1. 触点核心架构与代码级契约（`IHbTouchpoint`）

每一个 HB 界面元素（卡片、向导节点、按钮、菜单项、数据网格行）在进入产品运行时后，均被赋予一个确定性的触点身份。

### 1.1 Pascal 代码级核心接口契约
在 `Core\DeepBase.HB.Core.pas` / `DeepBase.HB.Touchpoint.Types.pas` 中正式冻结以下核心接口：


## 2. 证据驱动 UI 闭环（Evidence-Driven UI Evolution）

HB 触点引擎不仅负责产生事件，更借鉴 **AsWish 软件工程证据层** 的思想，构建 **用户行为变化可见化闭环**：

```
                    ┌───────────────────────────────┐
                    │    用户发生交互 (UI Action)   │
                    └───────────────┬───────────────┘
                                    ↓
                    ┌───────────────────────────────┐
                    │  产生行为证据 (TTouchEvidence) │
                    └───────────────┬───────────────┘
                                    ↓
                    ┌───────────────────────────────┐
                    │  版本差异对比 (Diff vs Prior) │
                    │   (例: HB v3.0 vs HB v3.1)    │
                    └───────────────┬───────────────┘
                                    ↓
                    ┌───────────────────────────────┐
                    │  自动定位断点 (Root Cause)    │
                    │   (例: 80% 用户卡在第二步)     │
                    └───────────────┬───────────────┘
                                    ↓
                    ┌───────────────────────────────┐
                    │  驱动产品自我演进与优化       │
                    └───────────────────────────────┘
```

## 3. 四自度量模型与核心计算公式

```
+---------------------------------------------------------------------------------------------------+
|                                      四自度量与数据计算体系                                       |
+---------------------------------+---------------------------------+-------------------------------+
|         【A. 自营销度量】       |         【B. 自承接度量】       |       【C. 自成长度量】       |
| • discovery_rate                | • self_onboarding_rate          | • review_rate                 |
| • self_transition_rate          | • self_resolution_rate          | • return_rate                 |
| • cross_feature_rate            | • completion_rate               | • Learning Gain: LG > 0       |
+---------------------------------+---------------------------------+-------------------------------+
                                  |         【D. 低客服度量】       |
                                  | • support_deflection_rate       |
                                  | • unresolved_without_support    |
                                  | • (客服降且流失升 = 违规驳回)   |
                                  +---------------------------------+
```

### 3.1 学习增益公式（Learning Gain, LG）
衡量系统是否因为用户的持续使用而真正降低了使用摩擦与认知负担：
$$\text{Learning Gain (LG)} = \text{第一次完成所需人工/解释成本} - \text{第二次完成同类任务所需人工/解释成本}$$
- **合格硬指标**：任何主干业务功能追踪必须保持 $\text{LG} > 0$。

### 3.2 自助化解率（Support Deflection Rate, SDR）
$$\text{SDR} = \frac{\text{通过产品内置自助向导成功解决的异常次数}}{\text{所有异常触发总次数}} \times 100\%$$
- **合格硬指标**：高频问题 $\text{SDR} \ge 80\%$。

## 4. 本地优先遥测与数据隐私保护（Local-First Telemetry Architecture）

桌面端（VCL/FMX）面向对数据安全要求极高的企业与私域用户，HB 触点引擎严格遵守 **Local-First 原则**：

1. **零明文 / 零 PII 泄露**：
   - 遥测日志仅记录触点 ID、状态机跃迁（如 `tp_waterfall: UNCERTAIN -> COMMITTED`）与耗时毫秒；
   - 严禁采集用户输入的文本内容、密码、客户名称或交易金额；
2. **本地高性能环形缓冲区（Local Ring Buffer）**：
   - 内存维护 10,000 条定长环形队列，掉电/退出时自动持久化至本地嵌入式 SQLite / WAL 数据库；
   - 支持本地离线聚合分析，无需强制联网上传即可为产品自身提供版本演进证据。

## 5. 断点快照自愈机制（Zero-Data-Loss Snapshot）

为支撑“低客服 + 高完成率”，向导类容器（`THbFacetWaterfall`、`THbDialog`、`THbVoiceDialog`）必须具备**会话快照持久化**能力：
- 用户在中途意外关闭窗口、切出查阅材料或发生异常时，控件自动持久化当前填单状态；
- 用户再次激活触点时，界面平滑恢复并温和提示：*“已为您恢复上次推演进度”*，彻底消灭因中断丢进度导致的客服求助。
